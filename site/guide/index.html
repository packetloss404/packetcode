01 / Install

Start with one binary.

PacketCode has prebuilt executables for Apple silicon and Intel Macs, x86-64 and ARM64 Linux, and x86-64 and ARM64 Windows. You don’t need Go to run a release download.

macOS & Linux

Open a terminal and run the installer. It detects your operating system and architecture, verifies the archive’s SHA-256 checksum, and installs into /usr/local/bin.

Terminal · macOS / Linux
curl -fsSL https://raw.githubusercontent.com/packetloss404/packetcode/main/install.sh | bash
Prefer to install without sudo?

Install into your user directory and add it to this terminal’s PATH:

Terminal · user install
curl -fsSL https://raw.githubusercontent.com/packetloss404/packetcode/main/install.sh | INSTALL_DIR="$HOME/.local/bin" bash
export PATH="$HOME/.local/bin:$PATH"

Add the export PATH line to your shell profile to keep it available in future terminals.

Windows

Run the installer in PowerShell. It chooses the Windows executable for your architecture.

PowerShell · Windows
& ([scriptblock]::Create((Invoke-WebRequest https://raw.githubusercontent.com/packetloss404/packetcode/main/install.ps1).Content))

The default location is %LOCALAPPDATA%\Programs\PacketCode\bin. Add that directory to your user PATH, or launch with its full path:

PowerShell · verify and launch
& "$env:LOCALAPPDATA\Programs\PacketCode\bin\packetcode.exe" --version
& "$env:LOCALAPPDATA\Programs\PacketCode\bin\packetcode.exe"
Download it your way.

All six native archives are on GitHub Releases. For version pinning, manual checksum verification, and Sigstore signatures, see the release guide. Go is only needed for building from source.

02 / Connect

Bring the model you use.

On first launch, choose a provider, enter an API key when required, and select a model. PacketCode saves your choices in ~/.packetcode/config.toml. You can change providers later with Ctrl + P or /provider.

Use your Codex ChatGPT login

For a Codex-enabled ChatGPT plan, sign in through the official Codex CLI first. Choose Sign in with ChatGPT; PacketCode reuses that credential store.

Terminal · Codex
codex login
packetcode --provider codex

Subscription login applies to the Codex provider. Hosted API providers use their own developer API keys.

Run a local model with Ollama

Start your Ollama daemon, then open PacketCode in another terminal. The default endpoint is http://localhost:11434, with no API key required.

Terminal · start Ollama
ollama serve
Another terminal · launch PacketCode
packetcode --provider ollama

Connect a hosted API or your own endpoint

OpenAI API, Anthropic, Gemini, and the other hosted API providers require their own keys. Use the provider picker or /provider add <slug> to configure one. Custom OpenAI-compatible endpoints are supported too.

See providers and models for credential sources, supported endpoints, and provider-specific setup.

03 / Your first session

Start where your code lives.

Open a terminal in the project you want to work on. Inside a Git repository, PacketCode uses the repository root as the boundary for its native file tools.

Terminal · from your project directory
packetcode --version
packetcode

Start with a focused request. A good first conversation asks PacketCode to explore before it changes anything:

Inside PacketCode · a first prompt
Explain how this project is structured and where its main tests live.

Then make the next request specific about the change and how to verify it: “Add validation to the signup handler and run the focused tests.”

A few keys you’ll use every day
Do thisPress or type
Send your promptEnter
Add a portable newline\ then Enter
Find a command or file/ for commands · @ for project files
Change provider or modelCtrl + P · /model
Open Agent View← on an empty prompt · /agents
Cancel active workCtrl + C

Your sessions are saved. Open /sessions to find one, or use packetcode --resume <session-id> from the same project.

04 / Permissions

Decide how much it can do.

The default Manual mode lets PacketCode read and search while asking before edits, shell commands, MCP tools, and background agents. Use Shift + Tab to cycle Manual, Accept Edits, Auto, and Plan.

Choose a mode for the task
ModeWhat it allows
Manual askRead and search automatically; ask before changes, commands, MCP tools, and agents.
Accept Edits accept-editsApprove file edits automatically; ask before shell commands, MCP tools, and agents.
Auto autoApprove file edits and shell commands automatically; MCP and other approval-gated tools still ask.
Plan read-onlyRead and search with mutations denied. The TUI also gives the model a planning instruction.
Bypass Permissions bypassApprove tools automatically unless an explicit deny rule matches. Enter deliberately with --trust or /trust on.

The code labels above are CLI values for --permission-mode. Bypass is outside the forward Shift + Tab cycle. Explicit deny rules remain effective.

When an approval appears, allow once, remember a rule for the session, or reject it. Use /permissions to inspect the policy and /permissions reset to revoke remembered session rules.

Know the boundary.

Tools run as your user, and model requests go to the provider you choose. Permission rules control tool decisions; they do not create an operating-system sandbox. Read the security and permissions guide when configuring hooks, MCP servers, or custom endpoints.

05 / Background agents

Give a focused task its own space.

Background agents get their own session, model selection, context, and result history. Start with a read-only review, then inspect it in Agent View:

Inside PacketCode · delegate a review
/spawn audit the current diff for correctness and test gaps
/agents

For an editing task, add --write:

Inside PacketCode · delegate an edit
/spawn --write fix the focused tests

Write-capable agents use separate Git worktrees based on the current commit. Uncommitted foreground changes are not copied into them, and completed work is preserved for you to inspect. PacketCode does not merge it automatically.

Completed results enter the foreground conversation when you explicitly inject or collect them. See the background-agent guide for result handling, budgets, and recovery.

06 / Repeatable work

Go from one turn to a workflow.

Use packetcode run when a script needs one agent turn. This example requests a read-only summary and returns a machine-readable result:

Terminal · one headless turn
packetcode run --permission-mode read-only --json "Summarize this repository and its test strategy."

The prompt is a positional argument. If an action needs interactive approval, a headless run exits with code 3 rather than approving it automatically.

For a reusable sequence of tasks, start with the built-in review workflow:

Inside PacketCode · review workflow
/workflows list
/workflows run review target="the staged diff"

Workflow definitions use TOML for ordered phases, parallel steps, optional verification, and retry caps. Extend your setup with stdio MCP servers and Agent Skills as you need them.

07 / Find your footing

A few useful answers.

My terminal says “command not found.”

Check the installation directory printed by the installer. For a user install on macOS or Linux, add ~/.local/bin to PATH in your shell profile. On Windows, add %LOCALAPPDATA%\Programs\PacketCode\bin to your user PATH, then open a new terminal. You can also use the executable’s full path.

My provider isn’t configured.

Open Ctrl + P, focus the provider, and press Ctrl + A to add a key. Codex reuses an official Codex CLI login; Ollama needs a running daemon. Hosted API providers need their own API credentials.

Why is it asking before an action?

Your current permission policy requires a decision. Read the requested action, then allow once, allow its displayed scope for this session, or reject it. Inspect the active rules with /permissions. Switching mode changes later actions and can re-evaluate a visible approval.

How do I diagnose a configuration problem?

Run the read-only doctor from your project directory. It checks configuration, credential sources, permissions, native tools, and configured integrations without opening the chat interface.

Terminal · diagnostics
packetcode doctor
packetcode doctor --check providers
packetcode doctor --json

For more answers, open troubleshooting or file an issue on GitHub with the command, version, and a redacted diagnostic report.

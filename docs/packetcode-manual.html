At a glance

Run packetcode from the project you want it to inspect. Type a request and press Enter. Use Shift+Tab to move from Manual to Accept Edits, Auto, or Plan. The footer always shows the effective policy.

packetcode --provider codex --model gpt-5.6-sol
/effort high
/spawn audit the current diff
/spawn --write fix the focused tests

Write agents use separate git worktrees. Their changes are not merged automatically, and their completed results do not enter foreground context until you inject or collect them.

Open printable commands

01Install and start

packetcode requires Go 1.24.2 or newer when building from source. Run it from the project directory you want it to work in; inside a Git repository it resolves the repository root as the native file-tool boundary.

macOS or Linux release install

curl -fsSL https://raw.githubusercontent.com/packetloss404/packetcode/main/install.sh | bash

Without sudo:

curl -fsSL https://raw.githubusercontent.com/packetloss404/packetcode/main/install.sh | INSTALL_DIR="$HOME/.local/bin" bash

Build from source

macOS / Linux

make build
./bin/packetcode

Windows PowerShell

$commit = git rev-parse --short HEAD
go build -trimpath -ldflags "-s -w -X main.version=dev -X main.commit=$commit" -o bin/packetcode.exe ./cmd/packetcode
.\bin\packetcode.exe

First-run setup

  1. Choose a provider.
  2. Enter an API key if that provider requires one.
  3. Choose a model. The selection is stored in ~/.packetcode/config.toml with mode 0600 on POSIX systems and best-effort user-only ACL hardening on Windows.

For an OpenAI Codex-enabled ChatGPT plan, authenticate with the official Codex CLI:

codex login
packetcode --provider codex

Choose Sign in with ChatGPT. The subscription provider reuses $CODEX_HOME/auth.json, or ~/.codex/auth.json when CODEX_HOME is unset. No API key is pasted into packetcode.

Startup options

packetcode
packetcode --provider codex
packetcode --provider codex --model gpt-5.6-sol
packetcode --resume <session-id>
packetcode --permission-mode ask
packetcode --permission-mode accept-edits
packetcode --permission-mode auto
packetcode --permission-mode read-only
packetcode --trust
packetcode --version
packetcode doctor
packetcode doctor --json
packetcode run --permission-mode read-only --json "summarize this repository"
packetcode skills list
packetcode acp
packetcode sugar login

--provider and --model override the saved default for one launch. --resume opens a saved session. --trust starts in Bypass Permissions mode.

Headless execution

A failed run reports its session ID and an interactive resume command when a session exists. Open saved history from the same directory before continuing. Completed tool actions are not rolled back, and opening a session does not repeat the failed prompt.

packetcode run [--provider NAME] [--model MODEL] [--permission-mode MODE] [--resume ID] [--json] <prompt...>

run executes one non-interactive agent turn through the provider, session, tool, policy, MCP, and compatibility runtime shared with the TUI and ACP server. The prompt is positional; stdin, --trust, --computer, and ephemeral-session modes are intentionally absent. An unavailable approval fails closed with exit 3; cancellation exits 130. Plain stdout contains only the sanitized final response. JSON is one schema_version: 1 object with ok, session/provider/model identity, output, total elapsed milliseconds, per-run input/output/cache usage, and an error on failure.

02Daily terminal workflow

Type a request at the bottom prompt and press Enter. Specific outcome-and-verification prompts work best:

Add validation to the signup handler and run the focused tests.

The foreground and ACP tools include root-scoped file/search/code intelligence, commands, skill retrieval, a per-session todo_write plan, and bounded HTTP(S) fetch. Fetch blocks private/loopback targets by default, disables ambient proxies, caps redirects/headers/body/time, and labels returned content as untrusted evidence; it is not a download or general web-search surface and is intentionally unavailable to background agents.

Completed turns move into normal terminal scrollback. The small live region is reserved for the current response, tool activity, prompt, context gauge, and permission mode.

The input grows to multiple rows. max_input_rows controls its displayed height, not maximum prompt length. Backslash-Enter works in every input state. Ctrl+J inserts a newline only when completion is closed; while the popup is open it moves the selected completion down. Alt+Enter works when the terminal reports Alt distinctly. Under Bubble Tea v1, Shift+Enter works only when the terminal maps it to Ctrl+J.

File mentions and slash commands

Type @ at a token boundary to search project files:

Compare @internal/app/app.go with @internal/jobs/manager.go and explain the handoff.

The selected file is expanded into bounded, root-scoped context when the prompt is sent. Avoid repeatedly attaching the same large file because each expansion consumes context.

Type / for slash-command completion. Use arrows or Ctrl+N/Ctrl+P to move, Tab to accept, and Esc to dismiss. Prefix a literal slash prompt with two slashes:

//explain why this is not a command

The model receives /explain why this is not a command as ordinary text.

Queue prompts while work is active

Submitting during an active foreground turn or compaction queues the prompt instead of interrupting it:

/queue
/queue drop 2
/queue resume
/queue clear

A failed turn or compaction pauses pending prompts. New prompts join the paused queue. Review it, then use /queue resume while idle, drop individual entries, or clear the queue to start fresh.

Queued prompts run in order. The listing shows up to the first 20 with one-based indexes.

Codex subscription and /effort

The codex provider rereads its OAuth file for every request. If its access token expires, packetcode exchanges the stored refresh token and atomically updates the same file while preserving unrelated fields. API-key-only Codex auth is not accepted here; use the openai provider for API-key billing.

Operating advice

Use lower effort for mechanical reads and edits; reserve high levels for architecture, subtle debugging, or synthesis. Effort cannot change while a foreground response is streaming.

04Permissions and approvals

The permission policy decides whether a tool call is allowed, shown for approval, or denied. It is a decision layer, not an operating-system sandbox.

Footer modeConfig profileBehavior
Manualask / balancedReads/searches/lists run; edits, shell, MCP, and model-initiated spawn_agent ask.
Accept Editsaccept_editsNative writes and patches run; shell, MCP, and model-initiated spawn_agent ask.
AutoautoNative edits and shell run; MCP, model-initiated spawn_agent, and explicitly gated tools ask.
Planread_onlyResearch runs; mutations are denied and the model receives a planning instruction.
Bypass PermissionsbypassTools run unless an explicit deny rule matches.

Shift+Tab cycles the first four modes, including during a turn. It affects subsequent tool calls and re-evaluates a visible approval, but cannot interrupt a command already running. Bypass is deliberately outside the cycle. Entering Bypass from Plan exits Plan atomically; /trust off restores the pre-Bypass profile (the profile that preceded Plan in that case) and preserves session rules, while /permissions reset is the revocation command.

Inspect and alter session policy

/permissions
/permissions profiles
/permissions profile ask
/permissions profile accept-edits
/permissions explain execute_command
/permissions rule execute_command ask
/permissions rule filesystem__* deny
/permissions reset
/plan on
/plan off
/trust on
/trust off

Session policy commands do not rewrite the saved configuration. The approval menu offers Allow once, Allow exact command this session (or Allow this tool this session), and Reject this request. A remembered shell approval matches exact command text in any working directory; other remembered approvals cover all arguments and paths for that tool. Running jobs keep their existing policy, and explicit denies still apply. /permissions reset revokes session rules, exits temporary Plan or Bypass state, and restores the startup policy.

Persistent policy rules

[permissions]
profile = "accept_edits"

[[permissions.rules]]
tool = "execute_command"
action = "deny"
command_prefix = ["rm", "-rf"]
reason = "refuse broad recursive deletes"

[[permissions.rules]]
tool = "filesystem__*"
action = "ask"

Rules can match exact tool names, suffix wildcards, mcp:*, all tools (*), exact command strings, or tokenized command prefixes. Explicit deny matches are safety floors; among other matches, evaluation runs from last to first, so the last match wins. Plan mode adds a hard read-only floor that allow or ask rules cannot override. Explicit deny rules remain active in Bypass mode.

05Sessions, context, cost, and recovery

Manage saved sessions

/sessions
/sessions resume <id-or-unique-prefix>
/sessions rename Fix authentication race
/sessions delete <id-or-prefix> --yes

Sessions are listed newest first. Resume and delete accept a full ID or unique prefix. Deletion is irreversible and requires --yes; deleting the active session first creates a replacement.

Understand the counters

CounterMeaning
Context occupancyEstimated/current tokens in the next model-facing request. It can fall after compaction.
Session input/outputCumulative provider-reported usage for one session.
Cost tallyCumulative estimated USD from provider/model pricing and session totals.

The request estimate includes the system prompt, transcript, tool arguments/results, tool schemas, and pending additions such as expanded @file context. Unknown model windows cannot show a meaningful percentage.

Compact long conversations

/compact
/compact --keep 15

Compaction makes a real request to the active model, records that request's usage, summarizes older history, and preserves the chosen recent tail plus complete tool-call/result groups. The default keeps 10 recent messages. Automatic compaction runs before an over-threshold turn when enough older history exists. Ctrl+C cancels an in-progress compaction.

Older oversized tool results may be shortened only in the model-facing copy; complete persisted transcript content remains available.

Cost, clear, transcript, and undo

/cost
/cost reset --yes
/undo
/transcript
/clear

/clear and Ctrl+L clear visible output but keep the session. /undo restores the latest session-scoped native write/patch backup; Git remains the durable rollback mechanism. Where a provider reports them, cache creation/read counts flow through sessions, jobs, /cost, and statusline JSON as subsets of input, not extra tokens. Pricing is an estimate, and unknown/local/subscription-backed models may display $0 even when provider plan limits apply.

06Background agents and worktrees

Each background agent is an independent job with its own session, context, provider/model, usage, cancellation, transcript, and result lifecycle.

Start bounded work

/spawn inspect the authentication flow for race conditions
/spawn --provider gemini --model gemini-2.5-flash audit the API handlers
/spawn --write implement the focused test fix
/spawn --computer production inspect the deployed service
/spawn --computer production --write migrate the app

Flags must precede the prompt. Read-only jobs inspect the selected project root. A remote foreground session inherits its active Packet Computer; from a local session, --computer <name> selects one. Each remote job owns a separate SSH/SFTP connection. Extra jobs queue after the configured concurrency limit. A user-entered /spawn starts directly; spawn approval applies to the model's spawn_agent tool. Tools used inside either child remain governed by the child's snapshotted policy.

The resolved computer, endpoint/root identity, and working directory are frozen before queueing. Nested agents inherit the target and cannot pivot. The computer's write/shell policy can restrict but never broaden the session policy.

Agent View

Open /agents, press Left Arrow from an empty idle prompt, or open one transcript with /agents <id>.

Each job owns a bounded todo_write list. Its row shows completed/total items and the current in-progress (or next pending) item; the list persists with the job so an abandoned run retains that evidence.

KeyAction
NFocus the new-agent composer.
Up/Down, J/KMove between agents.
PPeek at output.
Enter or OOpen the transcript.
CCancel an active agent.
IInject a terminal result into foreground context.
X or DIgnore a completed result.
EscClear a draft, return to the list, or close Agent View.

Use /jobs, /jobs <id>, /cancel <id>, and /cancel all from chat. Live transcripts preserve your scroll position unless you were already at the bottom.

/jobs resubmit lists jobs abandoned by a previous app exit and /jobs resubmit <id> re-runs one. This starts a new job from the saved prompt — nothing is resumed. The original keeps its cancelled state and all of its evidence, and the two records link both ways. One resubmit per job; a saved prompt over 32 KiB is refused rather than truncated.

Result lifecycle

Completed results are not silently inserted into foreground context. The terminal completion notification marks a result seen; injecting adds a bounded handoff; explicit parent collection marks it consumed; ignoring marks it ignored. collect_agent_results is a read-only tool and is normally auto-allowed unless an explicit rule changes it to ask or deny. Artifact manifests summarize changed files, worktree metadata, commands/tests, searches, child jobs, bounded previews, and errors. Full logs and files stay in the transcript/worktree.

Write-capable jobs

~/.packetcode/worktrees/<repo-key>/<job-id>
branch: packetcode-job-<job-id>
base: current HEAD

A write job requires Git and never edits the foreground checkout. Its base is committed HEAD; dirty foreground changes are not copied. On a Packet Computer, the worktree lives under the remote user's PacketCode state directory. Worktree creation fails closed instead of falling back to the registered checkout.

# Inspect a completed job
git -C <worktree-path> status --short
git -C <worktree-path> diff
git -C <worktree-path> log --oneline --decorate -5

# If the agent created a commit, integrate it deliberately
git cherry-pick <commit>
No automatic merge

Packetcode does not commit, merge, copy uncommitted edits, remove worktrees, or delete branches automatically. Do not assume a completed job has made a commit. Assign disjoint files to parallel writers or serialize them.

Limits and persistence

Defaults are four concurrent jobs, nesting depth two, and 32 jobs per process run. Job snapshots persist under ~/.packetcode/jobs/. Jobs active during an unclean exit recover as cancelled rather than resuming, and can be explicitly re-run with /jobs resubmit. Remote jobs are process-lifetime execution: there is no daemon or SSH reconnect-and-continue loop, and detached remote descendants may require operator cleanup. Arbitrary sub-agent clarification questions and foreground streaming of sub-agent output are not implemented.

07Workflows and loops

Workflows orchestrate ordered phases over the same job manager. A parallel step creates one job per fan-out item and joins the results.

/workflows
/workflows list
/workflows validate focused-review
/workflows run review
/workflows run --computer production review
/workflows run review target="the staged diff"
/workflows <run-id>
/workflows stop <run-id>
/workflows stop all

A built-in review workflow is immediately available. User definitions live in ~/.packetcode/workflows/*.toml; local project definitions in .packetcode/workflows/*.toml take precedence. Remote sessions load built-ins plus local user definitions; remote project discovery is deferred so workflow loading does not block the TUI on SFTP.

A remote foreground session routes the whole run to its active computer; from a local session, use --computer <name>. Every work agent, retry, and verifier uses that target. Each write-enabled workflow agent gets its own worktree, so later steps receive summaries rather than another job's unmerged files.

schema_version = 1
name = "focused-review"

[inputs]
target = "the current working tree"

[[phases]]
name = "analysis"

[[phases.steps]]
name = "review"
mode = "parallel"
bind = "review"
fan_out = ["correctness", "security", "test gaps"]
prompt = "Review {{.inputs.target}} for {{.item}}. Return evidence with file paths."

[[phases]]
name = "synthesis"

[[phases.steps]]
name = "synthesize"
mode = "single"
prompt = "Deduplicate and prioritize these findings:\n\n{{.steps.review}}"

[phases.steps.verify]
prompt = "Verify attempt {{.attempt}}. Candidate:\n{{.result}}"
provider = "codex"
model = "gpt-5.6-sol"
pass_contract = "packetcode-workflow-verdict-v1"

[phases.steps.retry]
max = 2

Every file declares schema_version = 1. /workflows validate <name> checks schema and templates without starting agents. Optional work-step fields are provider, model, system_prompt, and allow_write; continue_on_error = true belongs on a phase.

A verifier is a separate read-only job. It receives bounded work summaries and artifact previews, so selecting a different verifier provider sends that evidence to that service. It must return the packetcode-workflow-verdict-v1 block with an exact pass or fail; missing or malformed verdicts fail closed. retry.max counts additional attempts. Verifiers and retries count toward the same 16-agent guard, global limits, and token budget. Steps without verifiers remain explicitly unverified.

Repeat foreground work

/loop Continue reviewing and fixing the focused tests until complete
/loop 10m /workflows run review
/loop list
/loop stop <loop-id>
/loop stop all

Self-paced loops ask the model for a versioned packetcode-loop-decision JSON block, retain LOOP_DONE for compatibility, and stop after 25 iterations regardless. Interval loops run immediately and then on the interval (minimum one second). Ticks skip while foreground work is active or the prompt queue is paused. Stopping a loop removes its queued iterations; Ctrl+C stops self-paced continuation.

That scheduler ceiling is separate from the shared no-progress detector: foreground, background, and ACP runs stop earlier when the same tool executes repeatedly with identical arguments and identical results. The diagnostic names the call; changing output counts as progress.

Current orchestration limits

Explicit multi-stage pipelines beyond ordered phases/steps are not shipped. Workflow verification and bounded retries are process-local orchestration; loops are also process-local schedulers, not durable daemons.

09MCP, hooks, and statusline

MCP servers

Packetcode supports stdio MCP tools. At startup it launches enabled servers, performs initialize, sends notifications/initialized, loads tools/list, and registers names as <server>__<tool>.

[mcp.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/project"]
enabled = true
timeout_sec = 20
env_from = ["FILESYSTEM_SERVICE_TOKEN"]

[mcp.filesystem.env]
LOG_LEVEL = "warn"

Only a small environment allowlist plus env_from names and explicit env values reach the child; explicit values win. The timeout applies to initialization, discovery, and calls.

/mcp
/mcp status filesystem
/mcp tools filesystem
/mcp logs filesystem
/mcp restart filesystem

MCP calls use normal permission rules; match all with mcp:* or a server with filesystem__*. Startup failures do not prevent the TUI from opening. Logs use a bounded, redacted tail.

MCP limit

Streamable HTTP, prompts/resources, and live configuration reload are not supported. The reviewed Streamable HTTP trust contract pins exact origins/address classes, bounded bodyless same-origin redirects, disabled ambient proxies, system-root TLS, atomically bound target-only credentials, bounded credential-redacted output, per-call approval/revocation, and manual reconnect, but no URL field, transport flag, or HTTP client exists. Use /mcp restart <name> after a stdio process crash; restart PacketCode after changing configuration.

ACP server

packetcode acp runs the same engine over local stdio. Versioned _packetcode/* extensions expose provider/model overrides, saved-session list/load/rename, usage, permission mode, configured MCP tools, project file search, Markdown prompt-command discovery/expansion, and explicit session close. ACP agents receive the shared skill index/tool path. User-invocable skills are not yet listed in _packetcode/commands/list, whose catalogue currently contains Markdown prompt commands only.

Hooks

Hooks execute configured shell text in the project root: PowerShell on Windows and sh -c elsewhere.

[[hooks.user_prompt_submit]]
command = "cat .packetcode-context 2>/dev/null || true"
timeout_sec = 2

[[hooks.pre_tool_use]]
matcher = "execute_command"
command = "python scripts/guard-command.py"
timeout_sec = 5

[[hooks.post_tool_use]]
matcher = "patch_file"
command = "gofmt -w $(git diff --name-only -- '*.go') 2>/dev/null || true"
timeout_sec = 10
  • user_prompt_submit: successful stdout becomes extra prompt context.
  • pre_tool_use: non-zero exit blocks the tool call.
  • post_tool_use: successful stdout is appended to the result; failures are reported in appended hook output.

Native and custom statusline

The native line works without configuration and responsively prioritizes live operation, agents, provider/model, reasoning effort, context occupancy, project/branch, and cost.

[statusline]
command = "jq -r '\"\\(.provider.display_name) · \\(.model.id) · \\(.model.reasoning_effort) · \\(.context_window.used_percentage)%\"'"
timeout_sec = 2

The command receives JSON on stdin and may use packetcode-native fields or Claude Code-compatible aliases such as cwd, model.display_name, context_window.context_window_size, and context_window.current_usage. Hook and statusline stdout/stderr are capped at 64 KiB. A failed, empty, or timed-out statusline falls back to native output.

/statusline
/statusline refresh

10Architecture, terminal behavior, and security

Mental model

terminal input
    |
    v
Bubble Tea app ---- provider registry ---- active model stream
    |                    |
    |                    +---- OpenAI / Codex / Anthropic / ... / Ollama
    |
    +---- foreground agent ---- native tools ---- project root
    |          |                  |
    |          |                  +---- policy and approvals
    |          +---- transcript, usage, backups
    |
    +---- jobs manager ---- independent background sessions/worktrees
    +---- workflow engine ---- ordered phases and parallel fan-out
    +---- MCP manager / hooks / optional statusline process

The foreground agent owns visible conversation state. Background jobs own separate sessions. Provider streams and job callbacks enter the UI as messages; the terminal event loop remains the single owner of rendered state.

Terminal behavior

Finalized output goes to terminal-native scrollback; only active work remains in the live region. Provider and tool text is sanitized before display: terminal control sequences, mouse-mode toggles, clipboard operations, unsafe control bytes, destructive carriage-return rewrites, and malformed split UTF-8 are removed or normalized.

PacketCode keeps mouse tracking and alternate-screen mode disabled. CI checks normalized lifecycle renders at 72×24 and 100×30, exercises a live resize, and rejects unsafe terminal protocol sequences. Native Windows/ConPTY remains a manual release check.

Display hardening is not command safety

Sanitization protects terminal state. It does not make the underlying shell command, hook, or MCP process safe.

Security boundaries

  • Native file tools canonicalize project paths and reject directory or symlink escapes.
  • Read tools bound output and avoid binary content where appropriate.
  • Permission policy gates invocation; an allowed process runs with your account's authority.
  • execute_command, hooks, statusline commands, and MCP servers are not OS-sandboxed.
  • Cancelled local commands report the teardown mechanism, confirmation state, and surviving PIDs. POSIX process groups and Windows Job Objects provide that evidence; SSH teardown remains explicitly unconfirmed.
  • Worktrees isolate repository files, not network access, credentials, or arbitrary paths reachable by an allowed shell.
  • Custom model endpoints receive system instructions, conversation content, tool schemas, and tool results.
  • @file expansion sends the selected file content to the active provider.
  • Explicit deny rules remain the floor in Bypass mode.

Do not use --trust in unfamiliar repositories. Review .packetcode/, hooks, workflow definitions, and MCP commands first. Keep secrets in environment variables or provider stores; do not attach them with @.

11Diagnostics and troubleshooting

packetcode doctor
packetcode doctor --json
packetcode doctor --check config
packetcode doctor --check providers
packetcode doctor --check permissions
packetcode doctor --check project,state.worktrees

--check accepts a section or exact check ID, can be repeated, and can contain comma-separated values.

Codex unavailable

Run codex login and select ChatGPT sign-in. Confirm the OAuth file is present; use openai for API-key mode.

Model switch fails

Use /model for the exact account catalog, then run packetcode doctor --check providers. Fallback listing does not guarantee invocation access.

Unexpected allow or deny

Run /permissions and /permissions explain <tool>. Use /permissions reset to revoke session changes and restore startup policy, or /permissions profile ask to change only the active profile.

Write job failed

Run git status, git worktree list, and the project/worktree doctor checks. Failure closes safely without editing foreground files.

Job queued too long

Open /agents, compare active work against background_max_concurrent, and cancel stale jobs with /cancel.

MCP or hook failure

Use /mcp status <name> and /mcp logs <name>. Test hooks in the platform shell and restart packetcode after MCP changes.

Cannot scroll

Use terminal scrolling, Shift+PageUp, or tmux copy mode. /transcript opens persisted conversation history.

Context grows quickly

Use /compact, avoid repeated large mentions, inspect large tool/MCP results, and remember tool schemas are resent.

Cancel and exit safely

Ctrl+C cancels active foreground work, clears an idle draft, or exits at an empty idle prompt. Ctrl+D, /exit, and /quit also exit when appropriate. Stop scheduled/background work explicitly when you do not want it to continue through shutdown:

/cancel all
/workflows stop all
/loop stop all

12Advanced operating patterns

Research, synthesize, then write

  1. Enter Plan mode and ask independent read-only agents for correctness, testing, and security/documentation evidence.
  2. Continue your own inspection while they run; avoid anchoring every reviewer on one interpretation.
  3. Peek or open transcripts, then inject only results that affect the decision.
  4. Ask the foreground model for one reconciled design.
  5. Switch to Accept Edits or Auto and implement in one checkout—or use disjoint write jobs.
  6. Run a fresh read-only verification fan-out.
/plan on
/spawn audit correctness; cite exact files and lines
/spawn inspect cancellation, races, and cleanup paths
/spawn compare docs and tests against shipped behavior

Provider specialization

The foreground and background providers may differ. Use a fast model for inventory, a deep reasoning model for invariants, and a long-context model for synthesis:

/spawn --provider gemini --model gemini-2.5-flash inventory all call sites
/spawn --provider codex --model gpt-5.6-sol reason about the concurrency invariant

Each provider/model must be configured and valid. Job usage and cost remain separate after result injection.

Guarded automation and lean handoffs

Combine an accept_edits base profile with exact command rules and a fail-closed pre-tool hook. Prefer a finite workflow over a loop when the fan-out shape is known. Ask agents for conclusions, evidence paths, commands run, and unresolved risks—not raw logs. Compact at phase boundaries rather than after every turn.
